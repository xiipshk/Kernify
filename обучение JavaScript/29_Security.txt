## 1. XSS (Cross-Site Scripting) — Deep Dive

### 1.1 Типы XSS
```
┌─────────────────────────────────────────────────────────────────┐
│                        XSS CLASSIFICATION                       │
├─────────────────┬─────────────────┬─────────────────────────────┤
│  Reflected      │  Stored         │  DOM-based                  │
│  (Non-persistent)│ (Persistent)   │  (Client-side only)         │
├─────────────────┼─────────────────┼─────────────────────────────┤
│ URL param       │ Database        │ location.hash               │
│ → Server        │ → Server        │ → JS reads                  │
```

### 1.4 Defense: Context-Aware Output Encoding
```javascript
// Правило: КОДИРУЙТЕ ВЫВОД В ЗАВИСИМОСТИ ОТ КОНТЕКСТА!

// 1. HTML Body / Attribute context:
function escapeHtml(str) {
  return String(str)
    .replace(/&/g, '&')
    .replace(/</g, '<')
    .replace(/>/g, '>')
    .replace(/"/g, '"')
    .replace(/'/g, ''')
    .replace(/\//g, '&#x2F;');
}

// Использование:
<div>${escapeHtml(userName)}</div>
<input value="${escapeHtml(userInput)}">

// 2. JavaScript context (inside <script>):
function escapeJs(str) {
  return String(str)
    .replace(/\\/g, '\\\\')
    .replace(/'/g, "\\'")
    .replace(/"/g, '\\"')
    .replace(/\n/g, '\\n')
    .replace(/\r/g, '\\r')
    .replace(/</g, '\\u003C')
    .replace(/>/g, '\\u003E')
    .replace(/&/g, '\\u0026')
    .replace(/=/g, '\\u003D')
    .replace(/-/g, '\\u002D')
    .replace(/;/g, '\\u003B');
}

// <script>const user = '${escapeJs(userName)}';</script>

// 3. CSS context:
function escapeCss(str) {
  return String(str).replace(/[^a-zA-Z0-9]/g, c =>
    '\\' + c.charCodeAt(0).toString(16).padStart(6, ' ')
  );
}

// 4. URL context:
function escapeUrl(str) {
  return encodeURIComponent(str);
}

// <a href="/search?q=${escapeUrl(query)}">Search</a>

// 5. Используйте библиотеки: DOMPurify (sanitization),
// escape-html, js-xss, sanitize-html

import DOMPurify from 'dompurify';

// Для HTML content (richeditors):
const clean = DOMPurify.sanitize(dirtyHtml, {
  ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br'],
  ALLOWED_ATTR: ['href', 'target', 'rel']
});
element.innerHTML = clean; // БЕЗОПАСНО
```

### 1.5 Trusted Types (Modern Browser Defense)
```javascript
// Trusted Types — браузерный API для предотвращения DOM XSS
// Требует: 'trusted-types' в CSP или Content-Security-Policy

// 1. Определяем политику:
if (window.trustedTypes && trustedTypes.createPolicy) {
  const policy = trustedTypes.createPolicy('myPolicy', {
    createHTML: (input) => DOMPurify.sanitize(input),
    createScriptURL: (input) => {
      // Валидация URL для скриптов
      const url = new URL(input, location.origin);
      if (url.origin !== location.origin) throw new Error('Cross-origin script');
      return input;
    },
    createScript: (input) => {
      // Для inline scripts (если нужны)
      return input; // но лучше избегать inline
    }
  });
}

// 2. Использование (браузер БЛОКИРУЕТ string assignment без TrustedHTML):
element.innerHTML = policy.createHTML(userInput); // OK
// element.innerHTML = userInput; // TypeError!

// 3. CSP для принуждения:
Content-Security-Policy: trusted-types myPolicy; require-trusted-types-for 'script'
```

## 2. CSRF (Cross-Site Request Forgery)

### 2.1 Как работает CSRF
```html
<!-- Злоумышленник создаёт страницу: -->
<form action="https://bank.com/transfer" method="POST" id="csrf">
  <input name="to" value="attacker">
  <input name="amount" value="10000">
</form>
<script>document.getElementById('csrf').submit();</script>

<!-- Жертва заходит на страницу → форма сабмитится автоматически -->
<!-- Браузер ПРИКРЕПЛЯЕТ cookies (включая session) к запросу! -->
<!-- Банк думает: "это легальный запрос от авторизованного пользователя" -->
```

### 2.2 CSRF Tokens (Synchronizer Token Pattern)
```javascript
// Server-side (Express example):
const csrf = require('csurf');
app.use(csrf({ cookie: true }));

app.get('/form', (req, res) => {
  res.render('form', { csrfToken: req.csrfToken() });
});

app.post('/transfer', (req, res) => {
  // csurf middleware автоматически проверяет _csrf токен
  // из body, query, или header 'x-csrf-token'
  res.send('OK');
});

// Client-side:
<form method="POST" action="/transfer">
  <input type="hidden" name="_csrf" value="{{csrfToken}}">
  <!-- или в header для AJAX: -->
  <script>
    fetch('/transfer', {
      method: 'POST',
      headers: { 'X-CSRF-Token': '{{csrfToken}}', 'Content-Type': 'application/json' },
      body: JSON.stringify({ to: '...', amount: 100 })
    });
  </script>
</form>
```

### 2.3 SameSite Cookies (Modern Primary Defense)
```http
# Set-Cookie headers:
Set-Cookie: session=abc123; SameSite=Strict; Secure; HttpOnly
Set-Cookie: session=abc123; SameSite=Lax; Secure; HttpOnly  # Рекомендуемый default

# SameSite modes:
# Strict: Cookie НЕ отправляется ни при каких cross-site запросах
#         (даже при навигации по ссылке с внешнего сайта)
# Lax:    Cookie отправляется при "безопасных" cross-site навигациях
#         (GET ссылки, не формы/POST/iframe)
# None:   Cookie отправляется везде (ТРЕБУЕТ Secure!)
#         SameSite=None; Secure
```

### 2.4 Double Submit Cookie Pattern
```javascript
// Для SPA / stateless API:
function generateCsrfToken() {
  return crypto.randomBytes(32).toString('base64url');
}

// Login / Session creation:
const csrfToken = generateCsrfToken();
res.cookie('csrf_token', csrfToken, {
  sameSite: 'lax',  // или 'strict'
  secure: true,
  httpOnly: false  // JS должен читать!
});

// Client читает cookie и отправляет в header:
const csrfToken = document.cookie.match(/csrf_token=([^;]+)/)[1];
fetch('/api/action', {
  method: 'POST',
  headers: { 'X-CSRF-Token': csrfToken },
  credentials: 'include'
});

// Server проверяет:
if (req.cookies.csrf_token !== req.headers['x-csrf-token']) {
  return res.status(403).send('Invalid CSRF token');
}
```

### 2.5 Additional CSRF Defenses
```javascript
// 1. Custom Header (не может быть установлен cross-origin без CORS):
fetch('/api', { headers: { 'X-Requested-With': 'XMLHttpRequest' } });
// Server: проверяет наличие header

// 2. Origin / Referer header validation:
app.use((req, res, next) => {
  const origin = req.get('Origin') || req.get('Referer');
  if (origin && !origin.startsWith('https://myapp.com')) {
    return res.status(403).send('Forbidden');
  }
  next();
});

// 3. User interaction requirement (re-auth для критических действий):
// - Re-enter password
// - 2FA confirmation
// - CAPTCHA
```

## 3. Same-Origin Policy (SOP) & CORS

### 3.1 Same-Origin Policy Details
```javascript
// Origin = Scheme + Host + Port
// https://example.com:443 ≠ https://example.com:8443 ≠ http://example.com

// SOP блокирует:
// - DOM доступ: iframe.contentWindow.document (cross-origin)
// - JavaScript API: localStorage, IndexedDB, Cookies (read/write)
// - fetch/XHR: cross-origin запросы (без CORS)
// - WebSockets: origin проверяется при handshake
// - Canvas: tainted canvas (cross-origin images) → toDataURL() blocked

// SOP НЕ блокирует:
// - Навигация: window.location = 'https://other.com' (top-level)
// - Form submit: <form action="https://other.com"> (POST без чтения ответа)
// - Script/Link/Img tags: <script src="https://other.com/script.js">
// - CSS: <link rel="stylesheet" href="https://other.com/style.css">
// - Web Fonts: @font-face src(url(...))
// - iframe embedding (но не чтение содержимого!)
// - postMessage (explicit cross-origin communication)
```

### 3.2 CORS (Cross-Origin Resource Sharing) Deep Dive
```http
# Simple Request (нет preflight):
# - Method: GET, HEAD, POST
# - Headers: только CORS-safelisted (Accept, Accept-Language, Content-Language, Content-Type с ограничениями)
# - Content-Type: application/x-www-form-urlencoded, multipart/form-data, text/plain

Request:
GET /api/data HTTP/1.1
Origin: https://app.example.com

Response:
Access-Control-Allow-Origin: https://app.example.com  # или * (но не с credentials!)
Access-Control-Allow-Credentials: true  # если нужны cookies
Vary: Origin

# Preflight Request (OPTIONS) — для non-simple requests:
Request:
OPTIONS /api/data HTTP/1.1
Origin: https://app.example.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Content-Type, Authorization

Response:
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Credentials: true
Access-Control-Max-Age: 86400  # кэш preflight (сек)

# Затем настоящий запрос:
PUT /api/data HTTP/1.1
Origin: https://app.example.com
Content-Type: application/json
Authorization: Bearer token...

Response:
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
```

### 3.3 CORS Misconfigurations (Common Vulnerabilities)
```http
# ❌ ОПАСНО: Reflect Origin без валидации
Access-Control-Allow-Origin: https://evil.com  # если Origin: https://evil.com

# ❌ ОПАСНО: * с credentials
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true  # НЕВОЗМОЖНО по спеке, но некоторые серверы делают!

# ❌ ОПАСНО: Null origin (file://, sandboxed iframe)
Access-Control-Allow-Origin: null

# ✅ Правильно: Whitelist origins
Access-Control-Allow-Origin: https://app.example.com

# ✅ Для множественных origins — динамическая генерация:
# Server code:
const allowedOrigins = ['https://app.example.com', 'https://admin.example.com'];
const origin = req.get('Origin');
if (allowedOrigins.includes(origin)) {
  res.set('Access-Control-Allow-Origin', origin);
  res.set('Vary', 'Origin');
}
```

### 3.4 COOP / COEP (Cross-Origin Isolation)
```http
# Cross-Origin Opener Policy
Cross-Origin-Opener-Policy: same-origin
# Результат: window.opener = null для cross-origin попапов/iframes
# Защита от Spectre side-channels

# Cross-Origin Embedder Policy
Cross-Origin-Embedder-Policy: require-corp
# Требует: cross-origin ресурсы должны отдавать CORP header
Cross-Origin-Resource-Policy: cross-origin

# Вместе → Cross-Origin Isolation:
# - SharedArrayBuffer работает!
# - performance.measureUserTiming()
# - High-res timers (performance.now() с микросекундами)
```

## 4. Content Security Policy (CSP) — Complete Guide

### 4.1 CSP Directives Reference
```http
Content-Security-Policy:
  # Fetch directives (куда можно загружать ресурсы):
  default-src 'self';                    # fallback для всех fetch directives
  script-src 'self' 'nonce-{random}' 'strict-dynamic';  # JS
  style-src 'self' 'unsafe-inline';      # CSS (inline styles для CSS-in-JS)
  img-src 'self' data: https:;           # Images
  font-src 'self' https://fonts.gstatic.com;
  connect-src 'self' https://api.example.com wss://ws.example.com;  # fetch, WS, ES
  media-src 'self';                      # <video>, <audio>
  object-src 'none';                     # <object>, <embed>, <applet>
  child-src 'self';                      # iframe, worker (deprecated, используйте frame-src/worker-src)
  frame-src 'self' https://www.youtube.com;  # iframe
  worker-src 'self' blob:;               # Web Workers, Shared Workers
  manifest-src 'self';                   # Web App Manifest
  prefetch-src 'self';                   # prefetch/preload

  # Document directives:
  base-uri 'self';                       # <base href>
  form-action 'self';                    # <form action>
  frame-ancestors 'none';                # Кто может встраивать эту страницу (X-Frame-Options replacement)

  # Navigation directives:
  navigate-to 'self';                    # Куда можно навигировать (form submit, window.location)

  # Reporting:
  report-uri /csp-report;                # Deprecated
  report-to csp-endpoint;                # Modern (Reporting API)

  # Other:
  upgrade-insecure-requests;             # HTTP → HTTPS автоматически
  block-all-mixed-content;               # Блокировать mixed content
  require-trusted-types-for 'script';    # Trusted Types enforcement
  trusted-types myPolicy;                # Разрешить политику
```

### 4.2 Nonce-based CSP (Best Practice for Inline Scripts)
```html
<!-- Server генерирует уникальный nonce для КАЖДОГО запроса: -->
<script nonce="a1b2c3d4e5f6">
  console.log('This inline script is allowed');
</script>

<!-- CSP header: -->
Content-Security-Policy: script-src 'nonce-a1b2c3d4e5f6' 'strict-dynamic'

<!-- 'strict-dynamic': если скрипт с nonce загружает другие скрипты — они тоже доверяются! -->
<script nonce="a1b2c3d4e5f6">
  // Этот скрипт может динамически загрузить другие скрипты:
  const s = document.createElement('script');
  s.src = '/analytics.js';
  document.head.appendChild(s); // Разрешено благодаря strict-dynamic!
</script>
```

### 4.3 Hash-based CSP (Для статических inline scripts)
```html
<!-- Вычислите SHA256 от содержимого скрипта: -->
<script>console.log('Hello');</script>
<!-- sha256-base64: -->
<!-- echo -n 'console.log(\'Hello\');' | openssl dgst -sha256 -binary | base64 -->

<!-- CSP: -->
Content-Security-Policy: script-src 'sha256-XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX'

<!-- Для стилей: -->
<style>body { color: red; }</style>
<!-- sha256-YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY -->
Content-Security-Policy: style-src 'sha256-YYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYYY'
```

### 4.4 CSP Reporting & Monitoring
```javascript
// Reporting API endpoint:
app.post('/csp-report', express.json({ type: 'application/csp-report' }), (req, res) => {
  const report = req.body['csp-report'] || req.body;
  console.log('CSP Violation:', {
    directive: report['violated-directive'],
    blockedURI: report['blocked-uri'],
    sourceFile: report['source-file'],
    lineNumber: report['line-number'],
    scriptSample: report['script-sample']
  });
  res.status(204).end();
});

// Report-Only mode (для тестирования):
Content-Security-Policy-Report-Only: script-src 'self'; report-uri /csp-report
// Не блокирует, только репортит!
```

## 5. Dependency Security (Supply Chain)

### 5.1 Supply Chain Attack Vectors
```javascript
// 1. Compromised package (event-stream, ua-parser-js, node-ipc)
// 2. Typosquatting (lodash -> lodashjs, react -> raect)
// 3. Dependency confusion (private package name claimed on public npm)
// 4. Malicious maintainer / hijacked account
// 5. Build pipeline compromise (SolarWinds style)
// 6. Protestware (node-ipc, colors.js — intentional breakage)

// Real incidents:
// - event-stream (2018): flatmap-stream injected bitcoin stealer
// - ua-parser-js (2021): crypto miner в популярном пакете
// - colors.js / faker.js (2022): maintainer broke own packages
// - node-ipc (2022): protestware wiped files in Russia/Belarus
```

### 5.2 Defense Strategies
```bash
# 1. Lockfiles (package-lock.json, yarn.lock, pnpm-lock.yaml) — COMMIT THEM!
# 2. npm audit / yarn audit / pnpm audit
npm audit
npm audit fix
npm audit --audit-level=high

# 3. SCA Tools (Software Composition Analysis):
# - Snyk: snyk test, snyk monitor
# - GitHub Dependabot: авто-PR для уязвимостей
# - GitLab Dependency Scanning
# - OWASP Dependency-Check
# - Socket.dev (проверка на malware, suspicious behavior)

# 4. npm settings:
npm config set audit-level=high
npm config set fund=false
npm config set audit=true

# 5. Используйте npm ci (clean install) в CI:
# npm ci — строго по lockfile, быстрее, безопаснее

# 6. Проверяйте publishConfig:
# "publishConfig": { "access": "restricted", "registry": "https://npm.pkg.github.com" }

# 7. 2FA на npm аккаунте (обязательно для maintainers!)
npm profile enable-2fa auth-and-writes
```

### 5.3 Subresource Integrity (SRI)
```html
<!-- Для CDN ресурсов — гарантирует, что файл не изменён: -->
<script
  src="https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js"
  integrity="sha256-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx="
  crossorigin="anonymous">
</script>

<!-- Генерация SRI: -->
# openssl dgst -sha384 -binary FILE | openssl base64 -A
# или: npx sri-hash -a sha384 lodash.min.js
```

### 5.4 Package Verification

## 6. Additional Attack Vectors & Defenses

### 6.1 Clickjacking (UI Redressing)
```http
# Защита:
X-Frame-Options: DENY
# Или современный CSP:
Content-Security-Policy: frame-ancestors 'none'

# Если НУЖНО разрешить встраивание:
Content-Security-Policy: frame-ancestors https://trusted-partner.com
```

### 6.2 Prototype Pollution
```javascript
// Атака: Object.prototype заражается через merge/assign
const malicious = JSON.parse('{"__proto__": {"polluted": true}}');
_.merge({}, malicious); // lodash < 4.17.12 vulnerable!

// Проверка:
console.log({}.polluted); // true — ВСЕ объекты заражены!

// Защита:
// 1. Обновляйте зависимости (lodash >= 4.17.12)
// 2. Object.freeze(Object.prototype) — ранний freeze
// 3. Используйте Map вместо plain objects для user data
// 4. Валидируйте ключи: Object.keys(obj).filter(k => !['__proto__', 'constructor', 'prototype'].includes(k))
// 5. Safe libraries: lodash.cloneDeepWith, merge с customizer
```

### 6.3 Open Redirects
```javascript
// ❌ Опасно:
app.get('/redirect', (req, res) => {
  res.redirect(req.query.url); // Атакующий: /redirect?url=https://evil.com
});

// ✅ Безопасно:
const allowedDomains = ['example.com', 'partner.com'];
app.get('/redirect', (req, res) => {
  const url = new URL(req.query.url);
  if (!allowedDomains.includes(url.hostname)) {
    return res.status(400).send('Invalid redirect');
  }
  res.redirect(url.toString());
});
```

### 6.4 Host Header Injection
```javascript
// ❌ Опасно: использование Host header для генерации ссылок
const resetLink = `https://${req.headers.host}/reset?token=${token}`;
// Атакующий: Host: evil.com → ссылка ведёт на evil.com

// ✅ Безопасно: используйте конфигурируемый base URL
const baseUrl = process.env.APP_BASE_URL; // https://app.example.com
const resetLink = `${baseUrl}/reset?token=${token}`;
```

## 7. Secure Headers Checklist
```http
# Полный набор security headers:

# HSTS (HTTPS only)

# CSP
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-...' 'strict-dynamic'; ...

# COOP/COEP (Cross-Origin Isolation)
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

# Permissions Policy
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()

# Other
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Cross-Origin-Resource-Policy: same-origin  # для своих ресурсов

# Cookie flags (в Set-Cookie):
# Secure; HttpOnly; SameSite=Lax (или Strict); Path=/; Domain=example.com
```

## 8. Browser vs Node.js Security Context

| Feature | Browser | Node.js |
|---------|---------|---------|
| **SOP / CORS** | Enforced by browser | Application responsibility |
| **CSP** | Enforced by browser | Not applicable (but can proxy) |
| **Cookies** | HttpOnly, Secure, SameSite | Manual handling (cookie-parser) |
| **XSS** | DOM sinks, Trusted Types | Template injection (server-side) |
| **CSRF** | SameSite cookies, tokens | SameSite cookies, tokens |
| **Dependency Security** | npm packages in bundle | Direct dependencies + transitive |
| **Prototype Pollution** | Client-side objects | Server objects (req.body, query) |
