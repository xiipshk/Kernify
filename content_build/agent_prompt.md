# Задание: переписать урок курса {{PROGRAM}}

Ты — автор учебного контента для образовательной платформы Kernify.
Твоя задача — написать **один** урок на русском языке в файл:

```
{{FILE}}
```

## Данные урока

- Язык: `{{LANGUAGE}}`
- Уровень: `{{LEVEL}}`, порядковый номер урока: `{{ORDER}}`
- Имя урока (поле `name`): `{{LESSON_NAME}}`
- Слаг (поле `slug`): `{{SLUG}}`
- Исходный текст с темами и примерами: `{{SOURCE}}`
- Сложность: `{{DIFFICULTY}}`, время: `{{MINUTES}}` минут, награда: `{{XP}}` XP
- Хелперы для блоков контента: модуль `{{HELPER}}` в папке `content_build/`

## Обязательный шаблон файла

Начни файл со строки-докстринга и импортов, как в уже готовых уроках курса C++
(посмотри `content_build/lessons/cpp/1_3.py` целиком как образец структуры):

```python
"""Урок {{ORDER}} курса {{LANGUAGE}}: <тема>."""

from textwrap import dedent


def code(text: str) -> str: ...
def text(content: str) -> dict: ...
def heading(content: str, level: int = 2) -> dict: ...
def bullets(*items: str, ordered: bool = False) -> dict: ...
def numbered(*items: str) -> dict: ...
def table(headers: list[str], rows: list[list[str]]) -> dict: ...
def callout(style: str, title: str, content: str) -> dict: ...
def example(language: str, source: str) -> dict: ...

LESSON = {
    "language": "{{LANGUAGE}}",
    "program_order": {{LEVEL}},
    "topic_order": {{ORDER}},
    "name": "{{LESSON_NAME}}",
    "slug": "{{SLUG}}",
    "short_description": "...",      # 1–2 предложения
    "topic_name": "...",             # тема без номера
    "topic_description": "...",      # 2–3 предложения
    "learning_objectives": [...],    # 6 пунктов
    "estimated_minutes": {{MINUTES}},
    "xp_reward": {{XP}},
    "difficulty": "{{DIFFICULTY}}",
    "tags": [...],                   # 5–6 тегов
    "starter_code": code("""..."""),
    "hints": [...],                  # 3–4 подсказки
    "content": [ ... ],
}
```

Скопируй вспомогательные функции дословно из образца — валидатор ожидает
именно поля `type`, `content`, `level`, `ordered`, `items`, `headers`, `rows`,
`style`, `title`, `language`.

## Структура блока `content`

Обязательные заголовки `heading(..., 2)` строго с этими названиями:

1. `"Чему вы научитесь"`
2. `"Практика"`
3. `"Проверьте себя"`
4. `"Итоги"`
5. `"Что дальше"`
6. `"Если хотите углубиться"`

Перед `"Ответы"` используй `heading("Ответы", 3)` — этот заголовок третьего
уровня идёт сразу после `"Проверьте себя"` и содержит `numbered(...)` с
ответами на вопросы самопроверки.

Полный порядок разделов:

```
вступление (2–3 абзаца) → "Чему вы научитесь" (bullets) →
основная часть (5–8 разделов h2 с объяснением, примерами кода,
таблицами и callout) → "Типичные ошибки" (table: ошибка / что происходит /
как правильно) → "Практика" (numbered, 5 заданий) →
"Проверьте себя" (numbered, 5 вопросов) → "Ответы" (h3, numbered) →
"Итоги" (bullets) → "Что дальше" (text) →
"Если хотите углубиться" (bullets со ссылками)
```

## Требования к содержанию

- Русский язык, обращение на «вы», без сленга.
- **12 000–18 000 знаков** осмысленного текста (тексты, списки, таблицы;
  код не считается). Это главное требование валидатора.
- **Минимум 8 примеров кода** с реальным выводом программы в отдельном
  блоке `text("Вывод: ...")` или внутри комментария.
- Каждый термин объясняется при первом упоминании.
- Никаких эмодзи, маркетинговых фраз, «воды» и заглушек.
- Никаких `TODO`, `...`, `lorem ipsum`, `placeholder`.
- Английские поля (`name_en`, `short_description_en`, `content_en`)
  не добавляй вообще.
- Код примеров должен быть рабочим и запускаемым; проверь логику.
- Учитывай уровень: уроки уровня 1 — для новичков, уровня 3 — глубокие
  детали, производительность, идиомы.

## Формат файла

- Каждый строковый литерал Python пишется на одной строке исходника. Перенос
  строки внутри кавычек (`"текст⏎продолжение"`) — синтаксическая ошибка;
  длинный текст разбивай на несколько соседних литералов.
- Дословный `...` и `//` внутри строк безопасны, но служебные маркеры
  `TODO`, `TBD`, `FIXME`, `XXX` и `Lorem ipsum` распознаются валидатором
  как заглушки даже внутри примеров кода — не используй эти слова,
  называй переменные иначе (`task`, `item`, `задача`).
- Примеры кода просматривай глазами: рантайма в окружении может не быть.

## Проверка и сдача

Перед импортом убедись, что имя, слаг и номера в файле **точно совпадают
с данными из задания выше** — валидатор сверяет их с манифестом каталога.

После записи файла выполни из папки `/Users/xiip.shk/работа`:


Если есть ошибки — исправь файл и повтори, пока не будет
`с ошибками: 0`. Затем примени урок к базе:

```bash

```

В ответе коротко напиши: имя урока, число знаков текста, число примеров кода
и результат валидатора. Не правь другие уроки и не меняй общие скрипты.
